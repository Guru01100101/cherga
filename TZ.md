# Технічне Завдання (ТЗ) — Проєкт "Cherga"

## 📌 Опис проєкту
Застосунок для створення та керування чергами для подій, кабінетів, видачі гуманітарної допомоги тощо. Дозволяє адміністраторам зручно керувати потоком людей, а користувачам — відстежувати своє місце в черзі в реальному часі зі свого смартфона.

## 🛠 Технологічний стек
*   **Бекенд:** Go (Golang) — для максимальної продуктивності та надійності.
*   **Фронтенд:** HTML + CSS + JS (з фокусом на розділення API та клієнтської частини).
*   **База даних (постійна):** PostgreSQL (адміни, налаштування черг, статистика).
*   **База даних (in-memory / реалтайм):** Redis (поточний стан черги, pub/sub для WebSocket).
*   **Деплой:** Hetzner (Docker) ➔ у майбутньому Cloud-платформи з автоскейлінгом.

## 👤 Ролі та Функціонал

### 1. Адміністратор
Власник черги (організація або волонтер).

**Керування акаунтом та чергами:**
- [ ] Реєстрація та авторизація (Логін/Пароль).
- [ ] Створення кількох черг одночасно (назва, опис).
- [ ] *Монетизація (в майбутньому):* Обмеження кількості активних черг для безкоштовного тарифу, безліміт для платного.
- [ ] Налаштування анкети: додавання/видалення полів (мінімум одне унікальне поле обов'язкове, напр. телефон).

**Керування точками входу (посиланнями):**
- [ ] Генерація унікальних посилань для доступу до черги.
- [ ] Генерація QR-кодів для цих посилань.
- [ ] Можливість тимчасово вимкнути або назавжди видалити конкретне посилання.

**Керування потоком (Панель Адміна):**
- [ ] Табличний вивід учасників черги.
- [ ] Пакетні та індивідуальні дії над учасниками: видалення, зміна статусу.
- [ ] Можливість обслужити поза чергою будь-який номер (в т.ч. пропущений).
- [ ] Відображення списку людей в черзі в реальному часі.

### 2. Персонал (Staff)
Люди, які безпосередньо обслуговують чергу (оператори).

**Робоче місце персоналу:**
- [ ] Отримання поточного та наступного номера на обслуговування.
- [ ] **Зміна статусів:** 
  - `В очікуванні` (waiting) — дефолтний статус.
  - `Обслуговується` (in_progress) — виставляється, якщо процес займає час.
  - `Пропущений` (skipped) — людина відсутня на місці. Виключається з ротації до ручного повернення.
  - `Завершено` (served) — обслуговування закінчено.
- [ ] **Цикл повернення:** Після статусу `Завершено` система шукає найменший номер зі статусом `В очікуванні` (або `Пропущений`, якщо його відновили).

### 3. Користувач (Клієнт)
Людина, яка стає в чергу.

**Реєстрація в черзі:**
- [ ] Табло черги (до логіну): показує всього людей, поточні номери в обслуговуванні, наступні 10 номерів та кнопку входу.
- [ ] Перехід за посиланням або сканування QR-коду.
- [ ] Заповнення анкети (дефолт: Ім'я + Телефон, або інші поля, налаштовані адміном).
- [ ] *Ідентифікація:* Унікальне поле анкети (телефон).

**Відстеження (Live-режим):**
- [ ] Відображення поточного, наступного та свого номера.
- [ ] Отримання сповіщень: "Ви наступний" та "Вас пропущено".
- [ ] Якщо отримано статус `Пропущений`: з'являється кнопка "Повернутися в чергу" (змінює статус назад на `В очікуванні`).

## 🔄 Логіка роботи черги (Алгоритм)
1. Користувачі додаються в кінець списку зі зростаючим порядковим номером (1, 2, 3...).
2. Адмін викликає поточний номер (наприклад, №1).
3. Якщо №1 немає на місці ➔ адмін тисне **"Пропустити"** ➔ викликається №2.
4. Якщо №2 обслуговано ➔ адмін тисне **"Обслужити"**.
5. **Цикл повернення:** Після "Обслужити" система шукає найменший номер, який ще не був обслугований (у нашому випадку це №1, якого пропустили). Відбувається виклик №1. 
6. Якщо №1 знову немає ➔ "Пропустити" ➔ викликається №3 і т.д.
