# Схема бази даних (PostgreSQL) — Проєкт "Cherga"

Тут описана базова структура реляційної бази даних. Для "гарячого" стану черги (хто за ким іде прямо зараз) використовуватиметься Redis, але ці таблиці в PostgreSQL будуть джерелом істини (Source of Truth) для налаштувань, статистики та історії.

## Таблиці

### 1. `admins` (Організатори / Власники)
Власники платформи, які створюють черги та керують персоналом.

| Поле | Тип | Опис |
| :--- | :--- | :--- |
| `id` | UUID (Primary Key) | Унікальний ідентифікатор |
| `email` | VARCHAR(255) | Email для входу (унікальний) |
| `password_hash` | VARCHAR(255) | Хеш пароля |
| `subscription_tier` | VARCHAR(50) | 'free' або 'premium' (для лімітів) |
| `created_at` | TIMESTAMP | Дата реєстрації |

### 2. `staff` (Персонал / Оператори)
Люди, які фізично обслуговують чергу (змінюють статуси).

| Поле | Тип | Опис |
| :--- | :--- | :--- |
| `id` | UUID (Primary Key) | Унікальний ідентифікатор |
| `admin_id` | UUID (Foreign Key) | Посилання на `admins.id` (Хто їх створив) |
| `login` | VARCHAR(255) | Логін або email для входу персоналу (унікальний) |
| `password_hash` | VARCHAR(255) | Хеш пароля |
| `name` | VARCHAR(255) | Ім'я працівника (напр. "Вікно 1", "Лікар Іванов") |
| `created_at` | TIMESTAMP | Дата створення |

### 3. `queues` (Черги)
Самі черги, які належать адмінам.

| Поле | Тип | Опис |
| :--- | :--- | :--- |
| `id` | UUID (Primary Key) | Унікальний ідентифікатор |
| `admin_id` | UUID (Foreign Key) | Посилання на `admins.id` |
| `name` | VARCHAR(255) | Назва (напр. "Видача продуктових наборів") |
| `description` | TEXT | Опис (необов'язково) |
| `is_active` | BOOLEAN | Чи відкрита черга зараз (за замовчуванням `true`) |
| `form_schema` | JSONB | Конфігурація анкети (які поля обов'язкові, яке є ідентифікатором) |
| `created_at` | TIMESTAMP | Дата створення |

### 4. `staff_queues` (Доступи персоналу до черг)
Таблиця Many-to-Many, щоб адмін міг призначати, який працівник має доступ до якої черги.

| Поле | Тип | Опис |
| :--- | :--- | :--- |
| `staff_id` | UUID (Foreign Key) | Посилання на `staff.id` |
| `queue_id` | UUID (Foreign Key) | Посилання на `queues.id` |

*(Первинний ключ складений: `staff_id` + `queue_id`)*

### 5. `entry_links` (Точки входу / Посилання)
Унікальні посилання/QR-коди, за якими люди стають у конкретну чергу.

| Поле | Тип | Опис |
| :--- | :--- | :--- |
| `id` | UUID (Primary Key) | Унікальний ідентифікатор |
| `queue_id` | UUID (Foreign Key) | Посилання на `queues.id` |
| `slug` | VARCHAR(50) | Унікальний хвіст посилання (напр. `hq-door-1`) |
| `is_active` | BOOLEAN | Чи працює зараз це посилання (`true`/`false`) |
| `clicks_count`| INTEGER | Лічильник переходів за цим посиланням (за замовчуванням 0) |
| `created_at` | TIMESTAMP | Дата генерації посилання |

### 6. `queue_entries` (Записи / Клієнти в черзі)
Історія та статичний стан людей, які стали в чергу. Кабінети клієнтів відсутні, ідентифікація відбувається за полями анкети.

| Поле | Тип | Опис |
| :--- | :--- | :--- |
| `id` | UUID (Primary Key) | Унікальний ідентифікатор |
| `queue_id` | UUID (Foreign Key) | Посилання на `queues.id` |
| `phone_number` | VARCHAR(20) | Номер телефону (основний ідентифікатор клієнта для MVP) |
| `client_name` | VARCHAR(100) | Базове ім'я |
| `status` | VARCHAR(50) | 'waiting', 'serving', 'skipped', 'completed' |
| `priority` | BOOLEAN | Чи має ця людина пріоритет (переміщена на 1 місце) |
| `ticket_number` | INTEGER | Порядковий номер у цій конкретній черзі (1, 2, 3...) |
| `form_data` | JSONB | Відповіді на кастомні питання анкети саме для цієї черги |
| `created_at` | TIMESTAMP | Час, коли людина стала в чергу |
| `updated_at` | TIMESTAMP | Час останньої зміни статусу (коли обслужили або пропустили) |
